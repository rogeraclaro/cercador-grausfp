# Phase quick-260924-09g Plan 01: Harden index.html keyboard rows, favourite a11y, main landmark, pagination and error retry Summary

One commit hardens `fp-cercador/frontend/index.html` and `fp-cercador/frontend/i18n.js` for keyboard, screen-reader and touch users, and fixes two latent bugs (pagination ellipses that never rendered, and a dead-end catalogue error state), while keeping click behaviour byte-identical.

## What Was Built

**Task 1 — Keyboard-operable rows (tracer).** Added `rowIsActionable(row)` and `activateRow(row)` methods to the `cercador` Alpine component, replacing the inline `@click` ternary on the results `<tr>` with `@click="activateRow(row)"`, `@keydown.enter.self`, `@keydown.space.self.prevent`, a `:tabindex` driven by `rowIsActionable(row)`, and `:aria-expanded` for grade-C rows. The FPO `<tr>` got the same Enter/Space handlers, a static `tabindex="0"`, and `:aria-expanded`. Added a focus-visible outline (`var(--warm)`, `outline-offset: -2px`) plus a background-tint fallback for `border-collapse` tables.

**Task 2 — Heart a11y/visibility, `<main>` landmark, pagination, heading order.**
- `.btn-fav:focus-visible` now forces `opacity: 1` with the shared focus outline; `@media (hover: none)` also forces `opacity: 1` so hearts are visible on touch devices.
- Both heart buttons got `:aria-pressed="String(<favourite?>)"`.
- `<main id="main">` now wraps the hero, filters, loading/error states and all three result views (name/occupation/FPO), sitting inside `x-data` between the topbar and the two modals.
- The pagination `x-for` items are wrapped in one `<span class="pagination-item">` root (Alpine only keeps the first child of a template root, which is why the ellipsis template never rendered), with a `display: contents` CSS rule to keep the flex gap. The `:key` changed from `JSON.stringify(item)` to `'p'+n`/`'e'+idx` since two ellipsis items previously produced identical keys.
- The occupation card heading changed from `h3` to `h2` (fixing h1→h3 skip), with the CSS rule renamed to `.ocup-card h2` — same four declarations, so no visual change.

**Task 3 — Plurals + error recovery.**
- Added five new i18n keys in both CA and ES: `index.itinerari.fpo_disponible_one`, `index.centres.count_one`, `index.centres.more_one`, `index.btn.exportTitle_one`, `index.error.retry`. Each of the four n-count call sites in `index.html` now picks `<key>_one` via a ternary when its `n` expression `=== 1`.
- `index.error` copy replaced (no emoji): CA "No s'han pogut carregar les dades del catàleg. Torna-ho a provar d'aquí a uns moments." / ES equivalent.
- `init()` was split: it now starts `catalogRequest = fetch(...)` immediately (with an inert `.catch(() => {})` to avoid an unhandled-rejection warning while auth is pending), awaits auth and applies `loggedIn`/`searchMode`/logged-in loaders unconditionally, then `await`s the new `loadCatalog(pendingRequest)` method. `loadCatalog` sets `state = 'loading'`, awaits the passed-in request (or starts a fresh one when called with no argument), and on success runs the same parse/index/ready logic as before, including the fire-and-forget centres fetches and the `?oferta=` deep link (now read fresh from `location.search` so a retry still honours it).
- The error `<div>` now contains a `<p x-text="t('index.error')">` and a `<button class="save-alert-btn" @click="loadCatalog()" x-text="t('index.error.retry')">` (empty parens are load-bearing — a bare method reference would pass the click event as `pendingRequest`).

## Deviations from Plan

### Owner override applied (not a self-directed deviation)

**1. [Orchestrator override] Fixed aria-label on both heart buttons instead of dynamic add/remove text**
- **Found during:** Task 2, before implementation (override supplied up front in the execution instructions)
- **Issue:** The plan's Task 2 A specified `:aria-label="favorites.has(row.id) ? t('index.fav.remove') : t('index.fav.add')"` (mirroring `:title`). The plan's own frontmatter flagged this as an open a11y question.
- **Resolution:** Per explicit owner decision, both heart buttons instead use a FIXED `:aria-label="t('index.filter.favs')"` (constant across state) plus the state-driven `:aria-pressed`, following the WAI-ARIA toggle-button pattern where the pressed state — not the label — communicates on/off. `index.filter.favs` was confirmed present in both CA (`'Favorits'`) and ES (`'Favoritos'`) blocks of `i18n.js` before use; no new key was invented. The `:title` tooltip keeps the original dynamic add/remove text unchanged.
- **Files modified:** `fp-cercador/frontend/index.html` (both heart buttons, results table and FPO table)
- **Commit:** b02419f
- **Verification note:** the plan's Task 2 automated verify command (`rg -c ':aria-label="(favorites|fpoFavSet)\.has'`) checks for the pattern the override replaced, so it was superseded by an equivalent check confirming both hearts carry `:aria-label="t('index.filter.favs')"` and `:aria-pressed="String(...)"` — both passed. All other Task 1/2/3 automated verify commands ran unmodified and passed.
