    **deploy/fp-cercador.service**
    Unitat systemd per al backend Flask via gunicorn. Assumpcions:
    - Usuari del VPS: `root` (CloudPanel per defecte) — ajustar si l'usuari és diferent
    - Directori del projecte: `/var/www/fp-cercador` (ruta típica CloudPanel)
    - Virtualenv: `/var/www/fp-cercador/venv`
    - L'arxiu `.env` resideix a `fp-cercador/backend/.env`

    ```ini
    [Unit]
    Description=Cercador FP España — Flask backend
    After=network.target

    [Service]
    Type=simple
    User=root
    WorkingDirectory=/var/www/fp-cercador/fp-cercador/backend
    Environment="PATH=/var/www/fp-cercador/venv/bin"
    EnvironmentFile=/var/www/fp-cercador/fp-cercador/backend/.env
    ExecStart=/var/www/fp-cercador/venv/bin/gunicorn \
        --workers 2 \
        --bind 127.0.0.1:5001 \
        --timeout 120 \
        --access-logfile /var/log/fp-cercador/access.log \
        --error-logfile /var/log/fp-cercador/error.log \
        app:app
    Restart=on-failure
    RestartSec=5

    [Install]
    WantedBy=multi-user.target
    ```

    Nota `--timeout 120`: el pipeline de refresh pot trigar 45s+; el timeout per defecte
    de gunicorn (30s) el mataria.

    **deploy/nginx-cloudpanel.conf**
    Config nginx per a CloudPanel. CloudPanel gestiona els vhosts a `/etc/nginx/sites-enabled/`.
    Aquest fitxer és un fragment `server {}` que el tècnic copiarà o adaptarà.

    ```nginx
    server {
        listen 80;
        listen [::]:80;
        server_name DOMINI_AQUI;  # p.ex. fp.example.com

        # Redirigir HTTP → HTTPS (CloudPanel gestiona el certificat Let's Encrypt)
        return 301 https://$host$request_uri;
    }

    server {
        listen 443 ssl http2;
        listen [::]:443 ssl http2;
        server_name DOMINI_AQUI;

        # Certificat gestionat per CloudPanel (Let's Encrypt)
        ssl_certificate     /etc/letsencrypt/live/DOMINI_AQUI/fullchain.pem;
        ssl_certificate_key /etc/letsencrypt/live/DOMINI_AQUI/privkey.pem;

        root /var/www/fp-cercador/fp-cercador/frontend;
        index index.html;

        # Frontend estàtic: servir directament
        location / {
            try_files $uri $uri/ /index.html;
        }

        # Proxy al backend Flask (gunicorn escolta a 127.0.0.1:5001)
        location /api/ {
            proxy_pass         http://127.0.0.1:5001;
            proxy_set_header   Host $host;
            proxy_set_header   X-Real-IP $remote_addr;
            proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header   X-Forwarded-Proto $scheme;
            proxy_read_timeout 130s;  # > gunicorn timeout (120s)
        }

        # Health check també fa proxy (sense /api/ prefix)
        location /health {
            proxy_pass http://127.0.0.1:5001;
            proxy_set_header Host $host;
        }
    }
    ```

    **deploy/DEPLOY.md**
    Guia de desplegament pas a pas. Contingut:

    ```markdown
    # Desplegament — Cercador FP España

    VPS: Contabo | OS: Ubuntu 24.04 | Panel: CloudPanel

    ## Prerequisits

    - Domini configurat apuntant a la IP del VPS (A record)
    - CloudPanel instal·lat i accessible
    - Accés SSH com a root (o usuari amb sudo)

    ## 1. Clonar el repositori

    ```bash
    cd /var/www
    git clone <URL_REPO> fp-cercador
    cd fp-cercador
    ```

    ## 2. Crear i activar virtualenv

    ```bash
    python3 -m venv venv
    source venv/bin/activate
    pip install -r fp-cercador/backend/requirements.txt
    deactivate
    ```

    ## 3. Configurar variables d'entorn

    ```bash
    cp fp-cercador/backend/.env.example fp-cercador/backend/.env
    # Editar .env i posar el valor real d'ADMIN_TOKEN
    nano fp-cercador/backend/.env
    ```

    ## 4. Crear directori de logs

    ```bash
    mkdir -p /var/log/fp-cercador
    ```

    ## 5. Instal·lar el servei systemd

    ```bash
    cp deploy/fp-cercador.service /etc/systemd/system/fp-cercador.service
    systemctl daemon-reload
    systemctl enable fp-cercador
    systemctl start fp-cercador
    # Verificar:
    systemctl status fp-cercador
    curl http://127.0.0.1:5001/health
    ```

    ## 6. Configurar nginx a CloudPanel

    **Opció A (recomanada) — via CloudPanel UI:**
    1. CloudPanel > Sites > Add Site > Static Site (o PHP si no hi ha opció estàtica)
    2. Document Root: `/var/www/fp-cercador/fp-cercador/frontend`
    3. Afegir el block `location /api/` i `location /health` des del fitxer
       `deploy/nginx-cloudpanel.conf` a la config nginx del site.
    4. CloudPanel > SSL/TLS > Let's Encrypt (activar HTTPS)

    **Opció B — manual:**
    ```bash
    # Substituir DOMINI_AQUI pel domini real a nginx-cloudpanel.conf
    sed -i 's/DOMINI_AQUI/fp.example.com/g' deploy/nginx-cloudpanel.conf
    cp deploy/nginx-cloudpanel.conf /etc/nginx/sites-available/fp-cercador.conf
    ln -s /etc/nginx/sites-available/fp-cercador.conf /etc/nginx/sites-enabled/
    nginx -t && systemctl reload nginx
    ```

    ## 7. Verificació final

    ```bash
    # Backend directe
    curl http://127.0.0.1:5001/health
    # Frontend via nginx
    curl https://DOMINI_AQUI/
    # API via nginx proxy
    curl https://DOMINI_AQUI/api/ofertes | head -c 200
    ```

    ## 8. Primer refresh de dades

    ```bash
    curl -X POST https://DOMINI_AQUI/api/admin/refresh \
      -H "Authorization: Bearer <ADMIN_TOKEN>"
    # Monitorar progrés:
    curl https://DOMINI_AQUI/api/refresh-status
    ```

    ## Gestió del servei

    ```bash
    systemctl status fp-cercador    # Estat
    systemctl restart fp-cercador   # Reiniciar (p.ex. després d'actualitzar el codi)
    journalctl -u fp-cercador -f    # Logs en temps real
    tail -f /var/log/fp-cercador/error.log
    ```

    ```

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet → nginx | Trànsit públic HTTP/HTTPS al servidor |
| nginx → gunicorn | Comunicació interna localhost (127.0.0.1:5001) |
| Admin → /api/admin/refresh | Token Bearer requerit (ja implementat a app.py) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-D-01 | Tampering | .env al VPS | mitigate | .env fora del document root, EnvironmentFile a systemd (no exposat per nginx) |
| T-D-02 | Information Disclosure | Logs d'error gunicorn | accept | Logs a /var/log/fp-cercador/, no accessibles via web; risc baix |
| T-D-03 | Elevation of Privilege | Servei com a root | accept | CloudPanel típicament usa root; canviar l'User= si el VPS té usuari dedicat |
| T-D-04 | Denial of Service | /api/admin/refresh sense rate limit | accept | Protegit per ADMIN_TOKEN; fase admin pot afegir rate limiting si cal |
</threat_model>
