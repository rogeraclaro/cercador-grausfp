# Phase quick-260924-0s3 Plan 01: Adapt index.html for mobile — table-to-cards, top bar, stacked modes, 44px touch targets Summary

One commit turns `fp-cercador/frontend/index.html`'s results table into readable cards at 320/390/768px (main table and FPO table alike), fixes topbar/mode-toggle wrapping, and adds 44px touch targets under `(pointer: coarse)` — verified end-to-end with a headless-Chrome Playwright harness (`mobile_check.py`, left uncommitted in the quick-task directory) that also asserts desktop (>768px) stays pixel-identical to base commit `9b3edf2`.

## What Was Built

**Task 1 (tracer) — harness + main-table cards.** Built `mobile_check.py`: a Playwright (`channel="chrome"`) harness that serves `index.html` from either the working tree or `git show 9b3edf2:...`, mocks `/api/ofertes` (real 12,894-record fixture), `/api/auth/me`, `/api/centres/*` and `/api/fpo/especialitats` (3 fixtures covering a normal row, an empty-data row, and a long-title row), and runs seven check groups (`cards`, `fpo`, `topbar`, `toggle`, `touch`, `overflow`, `desktop`) selectable via `--only`. In `index.html`: added `:class="{'cell-empty': ...}"` to `td.col-codi`/`td.col-niv` and `:data-label="t('index.col.niv')"` to `td.col-niv`; removed the old `.table-wrap`/`.results-table`/`.col-nom` horizontal-scroll rules from the existing `@media (max-width: 768px)` block; added a new end-of-sheet `@media (max-width: 768px)` block making the table/tbody/tr `display: block`, the `thead` visually hidden (sr-only technique + `clip-path: inset(50%)`), main rows `display: flex` cards with a `var(--warm2)` tint on hover/`.row-fav`/`:focus-visible`, meta cells reordered via `order` (grau, niv, codi, fam), a `· <label> ` separator built from `attr(data-label)`, `cell-empty`/`:empty` cells hidden, and the grade tag styled as a bordered 3px-radius pill with no separator.

**Task 2 — FPO cards, top bar, mode toggle, overflow gate.** Added `results-table--fpo` to the FPO `<table>` and `col-area`/`col-hores`/`col-ncursos` classes plus `:data-label`/`cell-empty` bindings (`fpo.col.hores`, `fpo.col.ncursos`, `fpo.col.nivell`) to its meta cells — the FPO table then falls into the exact same card CSS from Task 1 with no separate ruleset, in DOM order (no `order` overrides). Added a scoped override so the FPO code cell (its first meta cell) gets no separator and `margin-left: 0`. Added top-bar rules (`.topbar-inner` wraps with `justify-content: flex-end`, `.topbar-logo` pinned left via `margin-right: auto`, `.auth-greeting` hidden, `.auth-btn` `white-space: nowrap`) and mode-toggle rules (`flex-direction: column`, full-width 44px-min-height buttons). Ran the harness's `overflow` group to decide the `html, body, [x-data]` scroll-lock rule: it fails (offenders = FPO `<select>` elements) with the rule kept, matching the plan's documented out-of-scope case, so the rule was left in place.

**Task 3 — 44px touch targets, full verification, commit.** Added a single `@media (pointer: coarse)` block (declared after the mobile block, before `</style>`): `.lang-btn`/`.auth-btn`/`.save-alert-btn`/`.clear-btn`/footer links get `min-height: 44px` via `inline-flex` centering; `select`/`.mode-toggle button`/`.checkbox-label` get `min-height: 44px` directly; `.btn-fav` and `.badge-centres`/`.badge-itinerari-b[role="button"]` get `position: relative` plus a `::after` 44px hit area (centered translate for the heart, full-width/height-centered strip for the pill badges) so none of their own visual boxes change size. Ran the full harness (all 7 groups, no `--only`) and the Task 3 static gates, then committed exactly `fp-cercador/frontend/index.html` with the required Catalan subject and no attribution trailer.

## Overflow-x Decision (scope item 2)

**Kept** `html, body, [x-data] { max-width: 100vw; overflow-x: hidden; }`. With that rule's effect temporarily disabled by the harness's `overflow` group, `document.documentElement.scrollWidth` stays within the viewport at every scenario **except** FPO mode at 320px and 390px, where the offenders are:

```
overflow@320/ca/user/fpo: [{tag: SELECT, right: 612}]
overflow@390/ca/user/fpo: [{tag: SELECT, right: 612}]
```

These are the FPO filter bar's `<select>` elements (familia/area/especialitat/etc.), which render their native option text at an intrinsic width wider than 320–390px. Per the plan, fixing this would mean styling the FPO filter bar, which is outside the 4 approved scope items (cards, top bar, mode toggle, touch targets) — so the rule stays, and the FPO filter bar keeps the same horizontal-scroll safety net it already relied on before this change.

## Accessibility / UX Notes Recorded Per Plan

- **Sorting headers are unavailable in the card view.** The `<thead>` (and its `sortable`/`@click` header cells) is visually hidden (sr-only clip technique) at ≤768px, matching the plan's approved design — there is no card-view affordance to change sort order; users would need to rotate to a wider viewport or use it at ≥769px.
- **Table semantics may be lost by some screen-reader/browser engines** once `table`/`tbody`/`tr`/`td` become `display: block`/`flex` inside the card block, per the plan's accepted "otherwise accept" disposition. No ARIA `role="table"`/`row`/`cell` roles were added to compensate, as none were requested.
- **`.grau-tabs` buttons, `.pagination` buttons, `.btn-doc` and `.watch-btn` were intentionally left unresized.** They are not on the plan's approved touch-target list (`lang-btn`, `auth-btn`, `select`, `save-alert-btn`, `clear-btn`, `mode-toggle button`, footer links, checkbox/radio labels, `btn-fav`, `badge-centres`, `badge-itinerari-b`), so widening their hit areas would have expanded scope.
- **The harness's `fpo` check group uses mocked fixture data** (3 synthetic especialitats), not the real `/api/fpo/especialitats` payload. The orchestrator's follow-up real-browser pass at 320/390/768/1280px with live data and real fonts is authoritative for the final visual result, as called out in the plan's verification section.

## Harness Flake Investigated and Fixed (not a deviation — inside `mobile_check.py`, which is not committed)

While validating the `desktop` group, roughly half of repeated `render_desktop()` calls produced a screenshot missing the `.grau-tabs`/`.filter-bar` rows even though `Alpine.$data(...)`/`getComputedStyle` confirmed the DOM was already in the correct state at that point. This traced to Playwright's `page.screenshot(full_page=True)` intermittently stitching a stale frame for this specific page right after the animations-disabling `<style>` tag triggers a layout pass. The fix: wait for `document.documentElement.scrollHeight` to stay unchanged across 6 consecutive `requestAnimationFrame` callbacks, then `set_viewport_size` to that height and take a plain (non-full-page) screenshot. Verified pixel- and byte-identical across 10 consecutive renders after the fix; the `desktop` group then passed on 4 consecutive full runs.
